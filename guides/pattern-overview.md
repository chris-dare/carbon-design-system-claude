# Overview

> Pattern — from the official IBM Carbon Design System documentation.
> Source: https://carbondesignsystem.com/patterns/overview/

Patterns are best practice solutions for how a user achieves a goal. They show reusable combinations of components and templates that address common user objectives with sequences and flows.

## Universal patterns

The following patterns have been approved for universal use.

| Pattern                                                | Description                                                                                                                             |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| [Common actions](https://carbondesignsystem.com/patterns/common-actions)             | Frequently used actions that appear multiple times across different components and workflows                                            |
| [Dialogs](https://carbondesignsystem.com/patterns/dialog-pattern)                    | Prompted when the system needs input from the user or to give the user urgent information concerning their current workflow             |
| [Disabled states](https://carbondesignsystem.com/patterns/disabled-states)           | Used to completely remove the interactive function of a component                                                                       |
| [Disclosures](https://carbondesignsystem.com/patterns/disclosures-pattern)           | Used to disclose additional content or information about part of a UI.                                                                  |
| [Empty states](https://carbondesignsystem.com/patterns/empty-states-pattern)         | How to address moments in an app where there is no data to display to the user                                                          |
| [Filtering](https://carbondesignsystem.com/patterns/filtering)                       | The mechanism by which a user adds or removes data items from a displayed data set                                                      |
| [Forms](https://carbondesignsystem.com/patterns/forms-pattern)                       | A group of related input controls that allows users to provide data or configure options                                                |
| [Global header](https://carbondesignsystem.com/patterns/global-header)               | Covers using UI Shell components for within and between product navigation; introduces techniques for achieving consistency in products |
| [Loading](https://carbondesignsystem.com/patterns/loading-pattern)                   | Used when information takes an extended amount of time to process and appear on screen                                                  |
| [Login](https://carbondesignsystem.com/patterns/login-pattern)                       | Allows a user to gain access to an application by entering their user ID and password                                                   |
| [Notifications](https://carbondesignsystem.com/patterns/notification-pattern)        | An important method of communicating with users and providing feedback                                                                  |
| [Ready-only inputs](patterns/read-only-inputs-pattern) | Inputs for form components that users can review but not modify.                                                                        |
| [Search](https://carbondesignsystem.com/patterns/search-pattern)                     | An intuitive method of discovery, offering users a way to explore a website or application using keywords                               |
| [Text toolbar](https://carbondesignsystem.com/patterns/text-toolbar-pattern)         | A set of buttons and menus that allows users to edit text.                                                                              |
